# NimDaydu

在 Chrome 侧栏显示网页声音的英文转录与中文翻译。采用 **本机 Moonshine Small 实时英文 + Parakeet 整句复核**；翻译可使用 Chrome 本地翻译、本机英中模型或已有 DeepSeek API。不需要新增付费服务或 Lightsail。

当前扩展版本 **0.5.1**，兼容本机服务 0.5.0。默认双语、自动保存。英文草稿实时显示，整句复核重新识别原音频，定稿后移入正文；中文等待完整句子，只在成功翻译后显示。Chrome 翻译超时或报错会自动重试，失败句子保留待补译，后续英文继续；不会自动切换翻译方式。

这台电脑的依赖、模型与扩展构建已经准备好。本机服务只监听 `127.0.0.1:8765`。

## 现在开始使用

1. 双击项目根目录的 **Start-NimDaydu.cmd**，启动本机服务。
2. 在日常 Chrome 打开 `chrome://extensions`，开启右上角 **开发者模式**，点击 **加载未打包的扩展程序**，选择：

   ```text
   E:\Projects\UniBuni\Nimdaydu\extension\.output\chrome-mv3
   ```

   选择包含 `manifest.json` 的整个文件夹。可以将 NimDaydu 固定在工具栏。
3. 在 Discord 网页版、YouTube、Slack 网页版或其他播放声音的标签页点击 NimDaydu 图标，再点侧栏底部的 **开始**。本机服务自动连接，不需要填写配对码或选择模型。

**从 v0.1 升级：**本次加入固定扩展身份，用来自动连接本机服务。若你已安装旧版，先导出需要保留的字幕，再移除旧 NimDaydu，并按第 2 步重新加载一次。之后的代码更新通常只需在扩展管理页点击“重新加载”。

**升级到 v0.4：**这台电脑的新依赖、Parakeet 模型及扩展构建已准备好。先导出需要的字幕，结束会话；双击停止、启动文件，再在 `chrome://extensions` 点击 NimDaydu 的“重新加载”，重新打开侧栏。原有 Chrome 翻译选择和显示设置保留。其他电脑运行一次 setup.ps1 补齐依赖和模型。

**v0.4 → v0.5：**无需安装新依赖或下载模型。结束会话、重启本机服务，在扩展管理页点“重新加载”并重新打开侧栏。自动保存默认开启，原翻译方式、显示方式和识别模型保留。

**v0.5.0 → v0.5.1：**修复点击“开始”报 `Cannot read properties of undefined (reading 'state')`。关闭旧侧栏，在 `chrome://extensions` 点 NimDaydu 的“重新加载”，再从声音所在网页重新打开侧栏。本次仅需更新扩展，已经运行的 0.5.0 本机服务可以继续使用。

安装扩展、下载模型与保存设置只需要第一次做。日常双击 **Start-NimDaydu.cmd**，再在目标网页开始字幕；用完先在侧栏点“结束”，等最后的译文完成，再双击 **Stop-NimDaydu.cmd** 关闭本机服务。可以给这两个文件创建桌面快捷方式。快捷键 **Alt + Shift + N** 打开当前标签页的侧栏；若被占用，可在 `chrome://extensions/shortcuts` 修改。

“结束”会停止采音和转录，模型服务仍驻留在内存中，以便快速开始下一次会话；关闭 Chrome 也不会退出这个独立服务。**Stop-NimDaydu.cmd** 会终止本项目的服务并释放模型内存。再次使用时双击启动文件即可，模型不需要重新下载。本版尚未实现随扩展自动启停服务。

启动服务仍是一次本机操作；Chrome 也要求你主动选择要捕获的标签页。默认配置无需手动调整。本版不会在后台自动采集其他标签页。

## 字幕如何显示

- 主页面默认显示中文主行与英文次行，英文始终可见。
- 默认识别方式“实时英文 + 整句复核”：Small 立即显示英文草稿，Parakeet 在独立线程重新识别原音频，再定稿、整理和翻译。约十秒长片段可能存在重叠，复核前合并重叠音频，减少重复词；短语会等待续接。音频仅保留在有上限的内存窗口，不写入磁盘。
- 识别中的英文立即进入底部“实时英文”区域，可能随更多声音修正词语。噪声中被识别引擎撤回的临时文字会移除，不阻塞后续句子。句子整理后原子替换为正文，避免重复显示；英文不等待中文翻译。
- 译文仍等待完整句子：模型定稿后，默认再等待 **0.8 秒**，合并可能的短语续接；日期和不完整短语通常等待约 **1.8 秒**。关联的下一句仍在识别时，会继续等它定稿。这些等待不会阻止英文草稿显示。
- 结合停顿、连接词、主题提示词和段落长度，整理成句与短段落。单个模型音频片段包含多句时会再拆分；未说完的话标注“语句未完”。
- 只翻译整理完成的句子。成功的中文只发布一次，后续句子继续追加；失败可以重试，已经显示的中文保持不变。设置为“仅中文”时等待完整译文，不显示英文草稿；存在恢复失败时保留英文供核对。
- 句子合并、标点整理不会通过 LLM 补造英文词语。这里采用保守规则，并非完整的语义理解模型。
- 暂停时原网页继续播放，但暂停识别。继续后，时间轴包含暂停期间的时间；暂停期间的音频不会补录。
- 短暂卡顿后音频可能集中到达；状态显示“正在追赶”，自动处理缓冲中的音频并恢复聆听，不需要重开会话。持续无法追上时仍会停止采集并保留已有字幕，避免无限延迟。

v0.4 在同组 40 段公开朗读中，词错误率从 Small 的 **4.20%** 降到整句复核的 **2.40%**；不代表游戏或非母语会议的准确率。94 秒公开人声实时重放中，首个非空英文预览 **1.23 秒**出现，全部音频帧处理完成。长段连续讲话会等整段复核，某些较早句子的定稿等待超过十秒；**0.8 秒是整理等待，不是中文总延迟保证**。详见 [测试记录](docs/benchmarks.md)。

## 支持范围

同一套 Chrome 标签页采音链路用于所有能播放音频的普通网页，无需分别配置 Discord、YouTube 或 Slack。界面会根据网址自动识别常见平台，包括 Discord、YouTube、Slack、Google Meet、Teams、Zoom、Twitch、哔哩哔哩与 Vimeo；未知网站使用通用网页模式。

这是**平台识别与通用采音**，不会读取 Discord 账号、Slack 消息或会议 DOM，也不依赖各平台的字幕功能。进入会话或播放视频后再开始；开始后固定音源，切换标签页不会自动换音源。

实际已验证：独立 Chrome 中的网页音频捕获、真实模型识别和离线翻译。尚未用你的真实 Discord/Slack 会议验收，也不能保证受保护媒体、所有播放器或公司受管浏览器均可捕获。Windows 桌面客户端、系统音频、麦克风、说话人身份、悬浮字幕暂未实现。

## 设置与导出

右上角 **设置** 在单独标签页打开，修改自动保存：

| 项目 | 默认 |
|---|---|
| 显示内容 | 中文和英文 |
| 文字大小 | 18 px；英文较小 |
| 译文整理等待 | 0.8 秒；下一次开始时生效，不延后实时英文 |
| 翻译方式 | 本机离线模型 |
| 语音识别 | Small 实时英文 + Parakeet 整句复核，CPU |
| 本机连接 | 自动连接 |
| 自动保存 | 开启，项目目录 `OUTPUTS` |

右上角 **更多** 提供搜索、双语 TXT / JSON 导出与会话结束后的清空。滚动回看时可点“回到最新”。

Chrome 单次翻译执行最多等待 8 秒，出错后销毁失效实例，下次尝试重新创建；同一句自动重试最多两次，间隔 1、3 秒。仍失败时显示 **恢复翻译**，保留缺失句子，点击后补译，无需重开采音。一次翻译失败不会清空其他句子；单句无响应也有等待上限。成功结果投递失败时复用该结果，不重新调用翻译模型。

**更多 → 导出诊断** 可保存最近的错误类别、重试次数、耗时、队列与本机音频/复核统计。诊断不包含音频、字幕、网页地址、连接令牌或密钥，只在内存中保留最近 200 条运行事件。出现整场中断时可导出，用于区分识别积压、连接断开和字幕视图关闭。

**设置 → 本机服务 → 语音识别** 可选择整句复核、Small 或 Medium，结束当前会话后生效，并记住选择。复核同时最多两个任务，音频窗口最多 90 秒，超过 30 秒的单次复核范围或持续积压会保留原识别结果并提示，不停止英文。它会比 Small 多占用内存和计算，不能保证每句话都更准确。

阅读器保留本次会话最近最多 5,000 句。v0.5 默认由本机服务把定稿字幕持续保存到 `E:\Projects\UniBuni\Nimdaydu\OUTPUTS`，已写出的历史不会因关闭 Chrome、重载扩展、清空侧栏或开始新会话而删除。关闭自动保存时，需手动导出要保留的字幕；旧版没有导出的历史无法补回。

目录示例（按 Asia/Singapore、UTC+08:00 命名）：

```text
OUTPUTS/
  2026-10-14/
    20261014-183045_youtube_<会话ID>/
      session.json
      transcript.txt
```

JSON 保存会话来源的标题/平台/域名、时间、识别模型、定稿英文和中文；TXT 便于直接阅读。标题不参与文件路径，避免非法字符或重名。每个会话有独立 ID，英文定稿后通常约一秒内更新，中文完成后补入同一份文件，正常结束再补写。写盘与 ASR 分开执行，文件采用临时写入再替换；失败会重试并提示，不会停止英文。突然强制结束服务或电脑断电仍可能丢失尚未写出的最后部分，不能保证崩溃时最后一句完整保存。

**设置 → 保存 → 自动保存** 可以关闭并记住选择，开关会同步到当前会话。关闭不删除已有文件；重新开启不会回填关闭期间的新句子，已保存英文的缺失译文可以继续补齐。用完仍应先点“结束”，等中文完成，再停止本机服务。`OUTPUTS/` 已排除在 Git 之外；清理历史时可手动删除对应会话目录。

自动保存和手动导出都只记录整理定稿的字幕，不保存原始音频或实时草稿；正常暂停/结束会整理最后的片段。JSON 保留原识别片段、句子、译文、段落及不完整标记；时间是模型估计，拆分句的时间按文本长度分配，不能当作精确词级时间轴。

关闭来源标签页会停止采集；最后一个字幕视图关闭后约 **10 秒**停止采集。本机服务断开会停止捕获并保留已显示字幕；重新开始会建立新会话。

## 翻译选择

| 方式 | 网络与费用 | 使用方式 |
|---|---|---|
| 本机离线模型 | 首次下载模型；使用时无 API 费用 | 默认，安装后即可使用 |
| Chrome 本地翻译 | Chrome 自行下载英中语言包 | 设置中选择并准备；日常 Chrome 已验证中→英翻译可用，仍需在插件中点一次准备 |
| DeepSeek API | 联网，产生已有 API 的用量费用 | 设置中选择，填写已有密钥并保存；不会自动切换到付费模式 |
| 关闭翻译 | 无 | 仅显示英文 |

离线翻译使用 Argos 英中 1.9 包中的 OPUS 模型，由 CTranslate2 在 CPU 上运行。完整、稳定的显示并不等于内容一定准确：专业术语、人名、口音、噪声和多人同时说话仍可能识别或翻译错。当前样本中的 NimDaydu 就曾被识别为 Nim Daedoo；英文保留识别结果，方便核对。

使用 Chrome 翻译：打开 NimDaydu 的 **设置 → 翻译方式 → Chrome 本地翻译 → 准备语言包**，等待“语言包已就绪”，再在声音所在标签页开始字幕。模型由 Chrome 按需下载，无需另找安装包。[Chrome 官方说明](https://developer.chrome.com/docs/ai/translator-api)。同一语言包在不同网页来源上的可用状态可能显示不同，准备按钮仍需在扩展内点击一次。

Chrome 使用专用翻译模型，但没有与当前 OPUS 模型完成同句英译中对照，不能保证更准确。2026-10-07 已在用户日常 Chrome 的官方测试页成功把公开中文测试句译为英文；此前隔离 Chrome 的下载超时不代表日常 Chrome 不可用。

项目根目录 `glossary.json` 可规范翻译输入的品牌拼写，比如 `discord → Discord`，避免被译成“不和”。它不会修改显示的英文，也不是任意中文术语词典。修改后重启本机服务。

DeepSeek 密钥仅存到本机 `.nimdaydu/providers.json`，不写入扩展存储，也不会在接口响应中返回。只发送完整英文句子及最近两句上下文；不发送音频。默认模型 `deepseek-flash`，关闭 thinking。也可以使用 `.env.example` 中的环境变量；设置页保存的值优先，移除密钥后本机记录会显式保持为空。

## 安装与开发

环境要求：Windows x64、Chrome 142+、Python 3.12、Node.js 22+、uv。这台电脑已具备；无需重新下载模型。

移动到其他电脑或依赖丢失时，在项目目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

脚本根据 `uv.lock` 与 `package-lock.json` 安装项目内依赖，下载 Small、Parakeet 及英中模型，再构建扩展。Python 使用 `local-service/.venv`，前端依赖在 `extension/node_modules`；无需 CUDA、WSL 或 Docker。高级选择 `setup.ps1 -Model medium` 会下载 Medium 并保存选择；已有用户不指定参数重复安装时保留原识别选择。

日常可双击根目录的 **Start-NimDaydu.cmd / Stop-NimDaydu.cmd**；在终端中等价操作为：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1
```

通常先在侧栏点“结束”，让最后一句完成。停止脚本检查进程路径及启动时间，避免结束其他程序。修改服务端代码后要停止并重新启动。

前端开发检查：

```powershell
cd extension
npm run typecheck
npm test
npm run build
```

然后在 `chrome://extensions` 点“重新加载”。构建输出为 `extension/.output/chrome-mv3`。`extension/identity.json` 是固定的公开身份信息，请保留；重新生成会改变自动连接所使用的扩展 ID。

Python 测试：

```powershell
cd local-service
.\.venv\Scripts\python.exe -m pytest -q
```

## 自行验证音频链路

```powershell
.\scripts\New-Sample.ps1
& .\local-service\.venv\Scripts\python.exe -m http.server 8800 --bind 127.0.0.1 --directory samples
```

Chrome 打开 `http://127.0.0.1:8800`，在该标签页点插件图标并开始，再播放测试音频。终端 Ctrl+C 停止样本服务器。样本由 Windows 已安装的英语语音合成，不采集麦克风。

完整服务链路基准（先结束浏览器字幕会话）：

```powershell
cd local-service
.\.venv\Scripts\python.exe benchmark_pipeline.py
```

结果写入 `artifacts/benchmark-pipeline.json`，记录英文预览、定稿、翻译及其时间，用于检查句子稳定和耗时，不是准确率评测。

复现浏览器音频短暂延迟后集中到达的情况：

```powershell
.\.venv\Scripts\python.exe benchmark_pipeline.py --sample-rate 48000 --provider none --pause-at 6 --pause-for 3 --output ..\artifacts\overflow-check.json
```

这会延后发送已捕获的音频，不会丢弃音频或模拟麦克风。`/health` 的 `audio` 字段提供最近一次会话的帧数、峰值队列、处理耗时与追赶次数；仅在本机内存中保留数值，不包含音频、字幕或密钥。

复现公开语音识别比较（不需要启动服务）：

```powershell
cd local-service
uv sync --frozen --group evaluation
.\.venv\Scripts\python.exe evaluate_asr.py --prepare
.\.venv\Scripts\python.exe evaluate_asr.py --models small medium parakeet
.\.venv\Scripts\python.exe evaluate_asr.py --models hybrid --limit 40
```

首次准备下载 Parakeet 与 LibriSpeech 测试子集；Small/Medium 需先通过 `download_models.py --models small medium` 准备。样本与结果写入忽略版本控制的 `artifacts/asr-evaluation/`。Parakeet 整文件分数与实时复核分数分别记录；只对相同样本比较词错误率。准备好的数据会复用，不重复下载。

## 常见问题

| 情况 | 处理 |
|---|---|
| 本机服务未连接 | 双击 Start-NimDaydu.cmd；已运行旧版时停止并重新启动 |
| 开始按钮不可用 | 在声音所在网页点一次 NimDaydu 图标；等待本机连接完成 |
| 自动连接被拒绝 | 重启本机服务；从 v0.1 升级需重新加载新版扩展，固定 ID 为 kmjdcdmffbieodadiegbnfjopendpblp |
| 等待语音或完整译文 | 确认选中网页在播放英文；默认双语会显示实时英文，仅中文模式等待句子整理与翻译 |
| 英文出现但翻译失败 | 设置中选择本机离线模型；缺少模型时运行 setup.ps1 并重启服务 |
| Chrome 语言包一直等待 | 切回本机离线模型；Chrome 模式约 3 分钟超时 |
| 中文暂时不更新 | 等待自动重试；出现“恢复翻译”时点击补译，英文仍继续 |
| 需要保留错误信息 | 更多 → 导出诊断，不包含字幕或密钥 |
| 整句复核出现降级提示 | 当前句保留实时识别结果；减轻本机负载，或在设置中使用 Small |
| 正在追赶 | 短暂积压会自动恢复，保留缓冲音频，无需重新开始 |
| 识别或发送持续积压 | 关闭高负载任务后重新开始；可查看 /health 的 audio 数值，已有字幕可导出 |
| 桌面客户端无字幕 | 本版捕获 Chrome 标签页，请使用网页版 |
| 全屏看不到侧栏 | 退出全屏或使用普通窗口 |
| 扩展被关闭 | 保持开发者模式开启，并确认 NimDaydu 已启用 |

## 按场景判断实用性

下表是基于当前实现和有限实测的预期，不是各场景都测过的准确率排名：

| 场景 | 当前可期待的用途 | 主要限制 |
|---|---|---|
| 清晰单人讲话、课程、普通视频 | 最适合辅助理解完整语句和回看 | 人名、地名、数字仍需核对 |
| 编程 / AI 技术演讲，一个人说话 | 适合跟上解释和讨论思路 | 函数名、API 名、缩写和命令不能保证逐字准确，不宜直接抄代码 |
| 母语者 / 非母语者混合的小组项目讨论，轮流发言 | 可辅助理解主旨、保存会后参考 | 口音、断句、语法不完整会降低效果；未做真实会议准确率验收 |
| Fortnite 等游戏直播、快语速、游戏音效 | 可辅助看懂部分交流和大意 | 玩家名、俚语、报点、多人重叠容易漏错；不适合依赖它即时操作 |
| 多人同时说话、噪声大或严重压缩 | 效果最不稳定 | 没有说话人分离，混合声音可能被拼成错误句子 |
| Discord / Slack / YouTube 等 Chrome 网页 | 使用同一标签页音频采集链路 | 不代表全部平台都已实机验收；桌面应用和麦克风暂不支持 |

英文预览在已测样本中约 0.6–1.3 秒首次出现，允许修订和撤回。中文先等原音复核与成句，再一次显示；游戏音轨中，模型估计句尾到定稿中位约 2.7 秒、最长约 9.4 秒，其他长语段可超过十秒。上述游戏重放使用离线翻译，不是 Chrome 翻译的时延保证。Chrome 翻译专门的长时验收仍未完成。

同组 40 段朗读的 WER 从 4.20% 降到 2.40%，只能证明该组样本的改善。它不能推导真实技术会议或游戏直播有 97.6% 的正确率。英文识别错了，翻译也可能把错误内容流畅地译出来；完整稳定的中文不等于每句都正确。详见 [实测记录](docs/benchmarks.md)。
